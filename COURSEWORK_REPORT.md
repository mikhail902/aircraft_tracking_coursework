# Курсовая работа

## Тема

**Получение данных о воздушных судах с использованием открытых API и сохранение результатов в PostgreSQL**

## 1. Цель работы

Цель проекта — разработать Python-приложение, которое получает географические координаты выбранных стран через Nominatim OpenStreetMap, получает актуальные данные о воздушных судах из OpenSky Network и сохраняет результаты в PostgreSQL.

## 2. Используемые технологии

В работе используются Python, библиотека `requests` для HTTP-запросов, `psycopg2` для работы с PostgreSQL, Nominatim OpenStreetMap для определения границ стран и OpenSky Network для получения текущих state vectors.

## 3. Получение координат стран

Для каждого из десяти выбранных государств выполняется запрос к Nominatim. API возвращает географические границы в виде bounding box: южная, северная, западная и восточная границы.

Полученные данные сохраняются в таблице `countries`.

## 4. Получение воздушных судов

OpenSky предоставляет endpoint `/states/all`, который позволяет получать текущие state vectors. В запрос передаются параметры `lamin`, `lomin`, `lamax`, `lomax`, ограничивающие область наблюдения.

Для каждого воздушного судна сохраняются ICAO24, callsign, страна происхождения, координаты, высота, скорость, курс, вертикальная скорость, код squawk и категория.

## 5. Проектирование базы данных

База данных состоит из двух таблиц.

### Таблица countries

| Поле | Назначение |
|---|---|
| id | первичный ключ |
| name | название страны |
| south | южная граница |
| north | северная граница |
| west | западная граница |
| east | восточная граница |
| created_at | время добавления |

### Таблица aircraft

| Поле | Назначение |
|---|---|
| icao24 | уникальный идентификатор транспондера |
| country_id | ссылка на контролируемую страну |
| callsign | позывной |
| origin_country | страна происхождения по OpenSky |
| longitude / latitude | координаты |
| baro_altitude | барометрическая высота |
| velocity | скорость |
| true_track | курс |
| vertical_rate | вертикальная скорость |
| geo_altitude | геометрическая высота |
| squawk | код транспондера |
| category | категория воздушного судна |
| observed_at | время наблюдения |

Связь между таблицами — один-ко-многим: одной стране соответствует множество наблюдаемых воздушных судов.

## 6. Класс DBManager

Для изоляции работы с базой данных реализован класс `DBManager`.

Метод `get_countries_and_aeroplanes_count()` использует `LEFT JOIN`, группировку по стране и `COUNT`, поэтому в результате присутствуют также страны, в которых на момент запроса не было найдено воздушных судов.

Метод `get_all_aeroplanes()` выполняет соединение таблиц и возвращает подробные данные о сохранённых воздушных судах.

Метод `get_avg_speed()` использует SQL-функцию `AVG` и игнорирует записи, в которых скорость отсутствует.

Метод `get_aeroplanes_with_higher_speed()` сравнивает скорость каждого воздушного судна со значением подзапроса `AVG`.

Метод `get_aeroplanes_with_keyword()` использует `ILIKE` и параметризованный запрос, поэтому поиск не зависит от регистра.

## 7. Принципы качества кода

Проект разделён на логические модули: API-клиенты, конфигурация, база данных и сервис сбора. Зависимости передаются в `AircraftCollector` через конструктор, что уменьшает связанность компонентов и соответствует принципу Dependency Inversion.

Все публичные классы и методы снабжены docstring. SQL-запросы параметризованы. Секреты подключения не хранятся в исходном коде и выносятся в `.env`.

Для повторного запуска используется UPSERT: существующая запись воздушного судна обновляется, а новая добавляется.

## 8. Ограничения

Nominatim и OpenSky имеют ограничения по частоте запросов. Кроме того, bounding box является прямоугольной областью, поэтому он не совпадает с юридической границей воздушного пространства. В учебной работе такой подход используется для пространственного ограничения запросов OpenSky.

## 9. Результат

В результате разработано приложение, которое получает данные из двух внешних API, преобразует их к единой структуре, сохраняет в PostgreSQL и предоставляет набор SQL-методов для анализа полученной информации.

## 10. Вывод

В ходе работы были закреплены навыки работы с REST API, HTTP-запросами, JSON, PostgreSQL и SQL. Реализовано разделение программы на модули и класс `DBManager`, позволяющий получать агрегированную и детальную информацию о воздушных судах.
